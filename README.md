\# Мини-Склад (версия 2.0)



Учебная конфигурация 1С:Предприятие с минимальным контуром складского учёта.

Цель — понять базовые механизмы: справочники, документы, движения по регистрам,

формы, подсистемы, командный интерфейс, программную фильтрацию данных, контроль остатков и печатные формы.



\## Состав конфигурации



\### Справочники



\*\*Товары\*\* (иерархический — опционально)



| Реквизит | Тип | Назначение |

|---|---|---|

| Наименование | Строка | Идентификация номенклатуры |

| Единица измерения | Справочник «ЕдиницыИзмерения» | Количество в движениях |

| Цена продажи | Число (15.2) | Автоподстановка в «Реализацию» |



\*\*Контрагенты\*\*



| Реквизит | Тип | Назначение |

|---|---|---|

| Наименование | Строка | Идентификация в документах |

| ТипКонтрагента | Перечисление (ЭтоПоставщик, ЭтоПокупатель, ПоставщикИПокупатель) | Фильтрация выбора в документах |



\### Перечисления



\- \*\*ТипКонтрагента\*\*: ЭтоПоставщик, ЭтоПокупатель, ПоставщикИПокупатель.



\### Документы



\*\*Поступление\*\*

\- Шапка: Поставщик, Дата, Номер, СуммаДокумента.

\- Табличная часть «ПоступаемыеТовары»: Товар, Количество, Цена, Сумма, ЕдИзм.

\- Движения: приход по регистру накопления «ОстаткиТоваров», запись в регистр «ОборотыТоваров».

\- \*\*Автозаполнение:\*\* При выборе товара реквизит «ЕдИзм» заполняется значением из справочника «Товары» (через серверный запрос).



\*\*Реализация\*\*

\- Шапка: Покупатель, Дата, Номер, СуммаДокумента.

\- Табличная часть «ПродаваемыеТовары»: Товар, Количество, Цена, Сумма, ЕдИзм.

\- Движения: расход по регистру накопления «ОстаткиТоваров», запись в регистр «ОборотыТоваров».

\- \*\*Автозаполнение:\*\* При выборе товара реквизит «ЕдИзм» заполняется значением из справочника «Товары» (через серверный запрос).

\- \*\*Контроль остатков:\*\* При проведении документа в оперативном режиме выполняется проверка остатков на момент времени документа. Если товара не хватает, документ не проводится, пользователю выводится сообщение.



\### Регистры накопления



\- \*\*ОстаткиТоваров\*\* (Вид: Остатки) — измерения: Товар; ресурс: Количество.

\- \*\*ОборотыТоваров\*\* (Вид: Обороты) — измерения: Товар; ресурс: Количество.



\### Отчеты



\- \*\*Остатки товаров\*\* — СКД-отчет, позволяет получать остатки на любую выбранную дату.

\- \*\*Обороты по товарам\*\* — СКД-отчет, позволяет получать обороты (приход, расход, итог) за выбранный период.



\### Печатные формы



\- \*\*Товарная накладная\*\* — печатная форма для документа «Реализация», реализованная через макет и команду в модуле менеджера.



\### Подсистема и интерфейс



Подсистема \*\*«МиниСклад»\*\* включает:

\- справочники «Товары», «Контрагенты»;

\- документы «Поступление товаров», «Реализация товаров»;

\- отчеты «Остатки товаров», «Обороты по товарам».



В свойствах подсистемы (вкладка \*\*«Командный интерфейс»\*\*) настроен вывод команд на панель навигации и панель действий.



\## Программная фильтрация контрагентов по двум типам



Штатный механизм «Связи параметров выбора» позволяет фильтровать только по \*\*одному\*\* значению перечисления. Для выбора двух типов (например, «Поставщик» и «ПоставщикИПокупатель») используется программный отбор через событие `НачалоВыбора`.



\### Особенности реализации



1\. \*\*Клиентский контекст (8.2 и выше)\*\* не позволяет напрямую обращаться к менеджерам перечислений (возникает ошибка «Переменная не определена (Перечисления)»).

2\. \*\*Решение:\*\* создание массива значений вынесено в серверную функцию `\&НаСервереБезКонтекста`, которая возвращает клиенту готовый массив.

3\. \*\*Программный отбор:\*\* Платформа 1С позволяет передавать отбор по реквизитам справочника при открытии формы выбора. Достаточно передать структуру с ключом `"ТипКонтрагента"` и массивом значений.



\## Расчёт сумм и контроль остатков



\### Табличная часть



Логика расчёта сумм в табличной части вынесена в отдельные процедуры, чтобы избежать дублирования кода и ошибок при вводе данных в произвольном порядке.

\- При изменении \*\*Цены\*\* или \*\*Количества\*\* — пересчитывается \*\*Сумма\*\*.

\- При изменении \*\*Суммы\*\* — пересчитывается \*\*Цена\*\* (только если Количество ≠ 0). После пересчёта цены сумма пересчитывается заново.



\### Контроль остатков (документ «Реализация»)



В модуле объекта документа «Реализация» реализован контроль остатков. Запрос получает остатки по товарам из документа и сравнивает с виртуальной таблицей остатков на момент времени документа. При нехватке товара выводится сообщение и отказ в проведении.

\## Запуск



1\. Открыть конфигуратор 1С:Предприятие.

2\. Загрузить конфигурацию из `src/` (или развернуть из `.cf`/`.cfе`).

3\. Обновить конфигурацию базы данных (F7).

4\. Запустить 1С:Предприятие (F5), открыть подсистему «МиниСклад».
